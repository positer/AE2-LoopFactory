# AE2LF 0.0.5 — 循环工厂使用与界面设计

本文是实施规格。验收状态与证据记录在本地 archive；这里列出的目标不能代替运行验证。

## 两条完整使用路径

**配方工厂：**主网接循环工厂样板供应器，将箭头朝向工厂子网。主网放循环工厂样板编码面板，录入输入/输出并编辑代码；上传页选择供应器，核对其子网名称、tag 和方向后上传。供应器接到 AE2 合成任务时保存输入到该任务的 source，执行代码，把 `put ... into source` 的产物送回主网。合成 CPU 继续按 AE2 的真实输出回收完成任务。

**常驻自动化：**普通 AE 网络放一个循环工厂网络终端，用手持编码器绑定它，创建 tag 并在世界中标记机器。把没有配方的循环工厂样板插入终端。红石每次从无信号变为有信号时启动一轮；持续高电平不重复触发。代码可以在显式等待后继续循环。关闭红石不强行取消正在执行的一轮。

## 网络、身份与权限

- 供应器箭头面是子网，其余面是主网；只允许定向模式。两侧节点不能通过供应器桥接频道、存储、标签或物流。AE 电仅主网向子网传输。
- 每个工厂有持久化 UUID、所在维度和锚点。名称可重复；上传列表同时显示坐标、方向和在线状态，不能凭名称猜测目标。
- 供应器是其子网的工厂所有者，优先于普通网络终端。主网中的多台供应器分别拥有自己的子网。
- 普通工厂终端、配方环解算终端和超算接口分别只能有一个生效。冲突采用稳定的维度/坐标顺序决定保留对象，额外机器显示重复设备原因。拆除保留对象或网络拆分后重新仲裁；卸载对象不能留下永远占用的静态标记。
- 所有编辑、绑定、上传、标记和缓存操作由服务端核验当前玩家、当前菜单、距离、AE 安全权限及实际网络归属。旧 UUID、跨维度失效锚点和被替换的机器不能自动绑定到碰巧同坐标的新工厂。
- 不主动加载区块；目标卸载时暂停并保留现场，区块重新加载且身份匹配后继续。

## 编码面板

它是 AE2 multipart 面板，不是整方块。保留原生配方录入模式、物品/流体数量编辑、背包和染色行为；增加“配方 / 工厂代码”切换，切换时保留尚未保存的草稿。

代码页顶部一行：左侧标题，右侧从左到右为上传按钮、AE2 回车符号保存按钮、循环工厂样板槽。下面是代码区；行号与错误标记在代码区内，底部状态行显示连接状态和当前错误，不在标题栏挤入额外大按钮。小分辨率使用滚动而不是缩小文字。

- 保存：先完整编译，再原子更新样板；失败保留原样板和草稿，定位错误行。Ctrl+S 与按钮相同。
- 配方页：输入、输出必须均有效；沿用原生数量与资源键组件，样板本身不因为预览转换为真实产物。
- 上传：列出同一主网的循环工厂样板供应器。每行包含工厂名、坐标、朝向、子网状态和空闲样板槽数。离线、跨权限、满槽目标显示原因，不能选择后静默失败。
- 确认目标后，以该供应器子网的 tag 声明重建 import，显示将使用的目标和编译结果；同名 tag 保留机器绑定。代码正文引用了目标不存在的 tag 时标红并拒绝上传，绝不把标签名替换成任意机器坐标。
- 上传把当前实体样板移入目标供应器的空槽，并写入子网绑定。整个操作在服务端一次验证后完成；失败样板留在编码槽。不能凭一次点击复制样板。
- 同一菜单关闭时不自动上传；未保存代码保存在该编辑宿主的草稿中。样板被取走后保存按钮禁用并保留草稿。

## 普通编辑器与手持交互

终端和手持编码器使用同一代码区样式。标题根据宿主显示“循环工厂网络终端”或“手持循环工厂编码器”。终端槽只接收无配方工厂样板；手持未绑定时允许编辑草稿，但不能把未绑定配方样板当作可运行任务上传。

- 空气/不可交互方块右键打开编辑器；Shift+右键这些目标清除手持绑定，不清除工厂本身的代码和 tag。
- 未绑定时，右键有效工厂网络的 AE 线缆、控制器或工厂终端绑定。右键供应器始终定位其箭头子网。
- 已绑定时，Tab+滚轮循环选择已有 tag；悬浮信息显示工厂名、当前 tag、已绑定机器数。没有 tag 时显示“无 tag”，尝试标记时提示“尚未创建 tag，请先在代码中 import”。
- 右键网络成员机器添加所选 tag；Ctrl+右键对直接相邻、同一方块类型且仍属于该工厂网络的机器做连通填充。搜索不穿越不同机器、网络边界或未加载区块。
- 绑定机器使用整个方块的半透明轮廓高亮；所选 tag 使用更明显颜色，其他 tag 降低透明度。仅向持有有效绑定编码器且有权限的玩家同步可见目标。
- 删除 tag 需要编辑 import；重新保存时仅删除被移除 tag 的绑定。网络暂时断开不删除坐标，实际物流每次重新验证成员资格。

## 语言与物流

`get` 未写数量时声明无数量上限的匹配来源，不提取或预占资源；`put` 未写数量时在来源剩余预算内尽可能转运当前可用且目标能接收的匹配资源。可写 `get 64 minecraft:iron_ingot from A`，表示后续输出最多从该来源转运 64 个匹配资源，实际库存以执行 `put` 时为准。数量、has、来源预算、供应器缓存余额和执行计数使用有符号 64 位整数，溢出报错，不截断或转 double。

`storage` 是执行所在工厂网络的可访问 AE 存储；供应器任务只能看到自己的子网 storage。`source` 是当前供应器任务的独立输入/返回边界；常驻终端没有外部分配材料，不把 source 偷换成整个主网。

工厂暂存是虚拟来源声明，不是实体库存。get 只声明来源、资源筛选、方向与数量预算，不抽取资源；put 才从这些来源向目的地提交实际转运。未使用和拒收的资源留在原机器。供应器的 source 是唯一明确存在的任务实物缓存：get from source 仍只声明来源，put into source 才提交返回输出。来源声明及剩余预算随执行状态保存。

明确 face 时查询对应面的能力；省略 face 时查询无面上下文。无面能力没有提供就报告不支持，不能宣称绕过第三方自身权限或擅自改其库存。原生物品、流体、FE 分世代适配；其他资源通过明确注册的存储适配器接入，不把任意自定义 capability 自动声称为通用存储。

`tag has id` 是当前网络内、已加载且可访问目标的匹配数量之和。比较支持 `< > <= >=`，非零为真。if/while 使用空格缩进，else 紧接对应 if；函数顶层声明并用同缩进 end 结束，保留字不可用作 tag/函数名。

`wait N tick/s/min` 接受正整数，20 tick/s。`redstone A N unit` 定义为对 A 发出强度 15、持续 N unit 的脉冲并等待；这里只使用一个数字，因此它表示时长。脉冲目标和剩余时间随执行状态保存。

不承诺通过静态分析判定任意程序终止。编码时拒绝能确定的非法循环，运行时检测无进展循环、限制递归和每 tick 指令量；有配方以完成一轮为目标，禁止无条件循环并保留有限总指令预算。仅无配方允许每条重复执行路径经过正时长 wait/redstone 的持续循环，不设累计生命周期指令预算。普通指令在当前 tick 顺序执行，不以跨 tick 或跳过来消化执行保护额度。运行错误暂停任务并保留实物，不能通过强行标记完成让 AE2 合成 CPU 收到虚构产物。

## 执行状态与恢复

显示“空闲 / 排队 / 运行到第 N 行 / 等待 N tick / 等待网络 / 等待目标区块 / 等待输出空间 / 代码错误”。错误包含行号和具体目标；可复制诊断文本。

保存代码快照、程序计数器、函数返回栈、等待时长、脉冲目标、当前任务输入、虚拟来源声明及其剩余预算、待返回输出及未完成任务队列。正在运行的任务使用启动时的代码快照；重新编辑不篡改一半执行的任务。重启恢复不能重领材料、重复输出或重新从第一行运行。

阻挡模式启用时每次发送一份配方，直到本轮代码完整结束、实物输入输出及预期产物全部结清，才接收下一批缓存并执行代码。副产物先返回、主产物部分或足量提前返回、主网无关同类物品、机器清空均不能代替完整运行结束。代码结束但仍有未结清资源时也保持阻挡。关闭时接受有上限的独立任务队列，满队列向 AE2 返回忙碌。每个任务独立缓存，不能互相偷用 source。供应器 source 缓存满时背压而非丢弃；普通工厂没有通用实物缓存。

拆除机器时将可物化物品按正常掉落处理；流体、FE 和其他资源随带数据的宿主物品保留或阻止有待处理资源时拆除，最终实现必须明确且经验证，不能仅丢出一台空机器。玩家取消需要看到残余资源处理结果。

## 验收要点

除了编译与资源检查，还必须验证：真正隔离的双网、AE 单向供电、合并/拆分后的唯一性、感应卡 FE 任务、输入和产物守恒、阻挡与满缓存、保存等待/函数栈后恢复、无权限上传拒绝、multipart 染色、两个客户端代码界面和世界高亮。每项在 archive 清单分别标记通过或未完成，不以测试数量替代完整流程。

### 资源反选

资源选择器支持 `A!(B,C)`，表示匹配 A 后排除 B、C，get、put 与 tag has 使用完全一致的匹配规则。例如 `minecraft::item!(minecraft:stone,minecraft:dirt)` 排除石头和泥土；`*!(neoforge::fe)` 排除 FE。支持通配符、类型排除以及嵌套反选，逗号附近允许空格；空排除列表、缺括号和尾随逗号均在保存前报告错误。

### 配方材料参数

有配方时允许 `P1`、`P2` 等代表配方有效输入材料，编号从 1 开始并在编码界面标明。参数匹配该次任务实际分配的精确资源键，保留组件/NBT 和 AE2 选定的替代材料；任务恢复后仍使用原始分配映射。get、put、has 和反选均可引用，例如 `get P1 from source`、`source has P2`、`minecraft::item!(P1,P2)`。无配方使用参数、P0、前导零和越界编号在编译/编码检查中报错。

### 配方编辑入口（用户补充）

普通 AE2 样板编码终端也必须能配置循环工厂样板的配方，并保留既有代码与网络绑定。手持编码器和普通工厂终端的编辑器只负责代码，不能修改配方。循环工厂样板编码面板提供明确的页面切换按钮，在原生配方页面和工厂代码页面之间切换。

### SFM 格式兼容目标

按 TeamDman/SuperFactoryManager 的 SFML.g4 对照实现独立语法前端，不能将 INPUT/OUTPUT 简单替换成 get/put。SFM INPUT 声明候选来源，OUTPUT 按筛选与数量提交实际转运；未被 OUTPUT 取用的资源应留在原机器。覆盖大小写无关关键字、NAME、双横线注释、EVERY 时间/红石触发、多触发器、INPUT/OUTPUT 两种语序、EXCEPT、RETAIN、EACH、WITH/WITHOUT 标签筛选、IF/THEN/ELSE/END、FORGET、侧面、槽位和 ROUND ROBIN。各语法与对应执行能力分别验收，未实现的能力必须显式报错。Pn 和 A!(B,C) 作为 AE2LF 扩展保留。源语法参考：https://github.com/TeamDman/SuperFactoryManager/blob/1.19.2/platform/minecraft/src/main/antlr/sfml/SFML.g4 。
