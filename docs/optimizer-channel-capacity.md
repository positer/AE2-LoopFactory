# 超算合成优化接口：频道扩容

原有无环合成计算加速继续按在线节点判定，仍占 1 个频道、消耗 8 AE/t。新增容量加成按接入当前网络的超算节点判定，在启动、缺电或频道不足时不依赖活动状态；这只提高容量，不供电，也不让超限设备无条件上线。

默认模式下，普通线缆 8→16，致密线缆和原生连接 32→64，控制器每面 32→64，无控制器网络总量 8→16。终端本身仍占用一个频道。多个终端只有一次加成；既有唯一服务选举保持单一接入者，并通过 AE2 的网络节点能力识别原生线缆。

有限模式以原始容量乘二，保留玩家配置的倍率；禁止承载节点保持零，无限模式保持原生最大值。智能线缆通过节点真实容量自动归一化到原有灯条，无需改写材质或传输协议。

容量成员集合由 `PathingService.addNode/removeNode` 维护。原生节点加入、离开、拆分和合并会触发重新寻路；没有静态全局网络缓存，也不向存档写入临时倍率。卸载沿用原生节点移除路径。独立网络和电力相连但频道隔离的子网不会共享加成。

`ChannelCapacityPolicy` 为不依赖游戏 API 的容量计算。两代分别适配 `PathingService` 的无控制器限制、`GridNode` 的节点容量、`GridConnection` 的连接容量。更新当前固定 AE2 版本时，需要核对这三个入口与重新寻路生命周期。

原生验收使用物理控制器、智能线缆和有限能量单元；负载是经真实 AE2 连接注册的托管节点。它验证实际频道分配与活动状态，不能表述为摆放了同等数量的实体机器。重复终端需跨越多个选举周期持续稳定，原有加速由真实 CPU 计划的 `OPTIMIZER_INTERFACE` 所有权另行验证。
## AE2 闪电科技（AE2LT / Thunderbolt）过载控制器

AE2LT 的过载控制器与高级过载控制器把频道分配交给 Thunderbolt 的最大流实现：控制器是容量源，每个控制器向网络注入固定供给（默认 128），线缆与连接不再是瓶颈。AE2 原生 BFS 下有效的「节点容量乘二」在这里不会改变可用总量，因此同一条合同在最大流网络上要落在供给上。

桥接由可选混入完成：在 Thunderbolt 求解入口按当前网络记录超算判定，在它读取单控制器供给时把供给乘二，并让 `calculateHighCapacityNetworkCapacity` 报告同一倍率。倍率仍是「每网络一次、不叠加」：多个超算终端只让判定保持为真。Thunderbolt 不在时，混入配置插件不应用任何桥接类，原生 AE2 寻路行为与既有三入口完全不变。

边界：该桥接只覆盖 Thunderbolt 的最大流网络（过载控制器及其高级／无线变体）。AE2 原生控制器网络继续走三个原生入口；两类控制器混用本来就是 AE2LT 判定的控制器冲突，不在此兼容范围内。
