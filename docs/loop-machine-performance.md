# 循环机器与合成计算评估

## 聚合器逐 tick 结算

标记磁盘的精确白名单逐个提取标记的完整 AE 物品键。模糊或反相选择需要发现网络里的其他键，因此枚举当前可用库存。拒收的产物保留为物质余额，下个 tick 重新结算。实测两代标记后一个 tick 消耗 1025 个木板，返回 4 个物质球并保留 1 点余额。

原生独立世界中，同一已启动的 ME 网络装入 256 种背景物品，另标记一个已耗尽的物品。通过同一反射入口测量旧版与新版完整服务调用，每个模式预热 120 次，再取 9 组、每组 50 次的单次耗时中位数。旧服务类取自 c9f0b3d 对应 JAR。最后一列按 20 TPS、一台在线机器折算，旧版每秒执行 4 次，新版 20 次。

| Minecraft | 模式 | 旧→新单次（μs） | 旧→新每秒占用（ms） |
| --- | --- | ---: | ---: |
| 1.21.1 | 精确白名单 | 294.0 → 19.1 | 1.176 → 0.382 |
| 1.21.1 | 模糊白名单 | 230.9 → 234.2 | 0.924 → 4.684 |
| 26.1.2 | 精确白名单 | 125.8 → 16.2 | 0.503 → 0.324 |
| 26.1.2 | 模糊白名单 | 73.1 → 45.7 | 0.292 → 0.914 |

精确白名单避免构造全网可用列表，在这个库存规模下抵消了执行频率增加的成本。模糊模式的每秒耗时增加，反相模式同样需要扫描。测量只覆盖物品未命中的在线扫描，成功转换、频繁拒收、大量设备同时工作与整服 TPS 的成本需按实际网络负载另测。

## 合成规划

超算接管无环订单，环解算终端接管实际选中配方中含环的订单。二者共用原生 AE2 配方图适配和 GlobalCraftingPlanner 的物料平衡、选方及强连通分量分析。普通调度现在从剩余有序配方表删除已完成的条目，后续批次只扫描仍有工作量的配方。含环订单在等待种子时只构建一次剩余产物集合，并在同一步的候选判断与种子补料间复用。所有余额和库存判断仍属于当前请求。独立 RecipeRingSolver 的有界广度优先搜索复用被支配候选的库存向量；进入搜索队列的向量保持独立。

| 工作负载 | 旧→新耗时（ms/单） | 旧→新分配（KiB/单） |
| --- | ---: | ---: |
| 超算，128 层链、1000 个成品 | 4.583 → 3.216 | 2499.8 → 2468.3 |
| 环订单，同一链前置自增种子 | 5.232 → 3.641 | 2774.2 → 2726.1 |
| 独立搜索，64 个等效增长配方、目标 100 | 0.960 → 0.494 | 437.1 → 291.0 |

基线为 c9f0b3d。每版使用三个独立 JDK 21 进程、256 MiB 固定堆，交替改前改后顺序。每个负载预热 120 次，计时 11 组，表中取各进程中位数再取中位数。逐单核对结果状态、批次顺序、种子、储备、物料余额和搜索预算计数。独立搜索耗时与在线环订单耗时分别计量。基准覆盖规划内核，未计入游戏的配方图采集、CPU 执行或第三方机器处理时间。剩余成本包含每轮余额重建、可执行配方查找和环搜索的支配关系比较；这些算法的最坏复杂度未因本轮修改而消失。
