# 合成撕裂者动态样板与循环卡

样板库存不再固定为 36 格。每行 9 格，界面以四行窗口向下滚动，最后一个已占用行之后保留一整行空槽。滑块采用 AE2 样板管理终端同款 `Scrollbar.BIG`（`ae2:big_scroller` / `ae2:big_scroller_disabled`），轨道直接引用原生 `patternaccessterminal.png` 的端点与中段。取走末尾样板会收缩空白尾部，内部空洞保留稳定槽位。空库存保留一行。容量仍受 Java 索引与可用内存的实际约束，没有人为样板数量上限。

循环卡安装后仍可放取样板。对于槽内样板指定的完整目标产物键（包括组件），只发布这些给定样板，多个手动配方均保留；缺料或配方失效时也不回退到同产物的自动配方。其他目标产物继续发布可编码的自动工作台、锻造台与切石机配方。取出手动样板后恢复对应的自动配方。

每个原生菜单只创建 36 个可见窗口槽。滚动请求携带顺序号，服务端先同步窗口内容，再确认行偏移；确认前拦截样板区域点击和物品快捷键。尾部收缩先保持原槽位映射，再由客户端收缩滚动范围并走同一确认流程，避免其他查看者移除尾部时改变在途点击的目标。Shift 放入使用完整真实库存，不局限于当前窗口。样板管理终端在动态尺寸改变时执行原生全量刷新，重建固定长度的客户端镜像并废弃旧条目标识。原生终端同步包有 128 条目与短整数槽位编码限制，因此撕裂者使用独立的分包载荷：每包最多 128 项，槽位采用 VarInt；客户端仍交给 AE2 原生终端更新方法处理。其他供应器的原生协议保持原样。

存档继续使用原生 `patterns` 列表与 `Slot` 整数索引，保留数量、组件及旧 36 格存档的位置。掉落与清空遍历全部实体样板，避免仅处理当前窗口。

AE2 原生内存卡的 `EXPORTED_PATTERNS` 组件上限为 256 项。这不是机器库存上限。超过 256 项时不导出样板组件，避免截断或崩溃；其余宿主设置仍按原生流程处理。导入不含该组件的内存卡不会清空样板库。大量样板应通过机器库存或样板管理终端搬运。

验证脚本使用独立新世界，最终产物与运行时类、资源逐项哈希对齐。NBT 往返证明序列化兼容；它本身不等于跨进程重新开档验证。原生客户端滚轮与库存点击消息另行验收。
