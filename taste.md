# Project Taste

- Native text-area content hooks run after the parent applies its scroll transform and viewport scissor. Draw text, selections and caret in content coordinates; subtract the precise native scroll only for visibility tests. Never apply a second scroll offset or recreate a screen-space clip inside the translated pose. Verify scrolling and cursor/click coordinates using native framebuffer evidence, not only top-of-document screenshots.

- Highlight complete source after edits, cache spans and intersect native visible-line ranges; never re-lex soft-wrapped fragments or recolor unrelated screens. Keep Unicode symbol discovery, resource tags and recipe references consistent with supported compiler syntax.
- Both factory languages treat unquoted `//` as a physical-line comment. Mask comments for parsing without changing source offsets or persisted source; preserve quoted slash pairs, old comment forms and original error line numbers. Comment scanner and SFM quote escaping must agree.

- Function default-channel logistics inherit the calling channel, including nested calls and suspended/restored MUST transfers; derive scope from persisted call-site return addresses instead of adding a second unsynchronized context stack. Explicit lexical channel blocks retain their own scope. Keep compiler keywords authoritative for native syntax highlighting and reserved names.
- Campaign completion must select explicit final attempts, reconcile source/JAR/runtime identity and preserve failed originals. Restore only known owned test files against the initial byte manifest after all native clients exit; archive changed helpers before replacement. PowerShell 5.1 JSON arrays must not acquire an extra pipeline array wrapper during manifest validation.
- Code ID input reads only the GUI carried stack. Preserve native caret/selection behavior when it is empty; left click selects the item ID, right click selects actual nonempty container contents or the ordinary item ID. Inspect copies through read-only public capabilities, deduplicate contents, and never drain or consume a resource to discover its ID.
- Viewer drop handlers are optional, version-isolated plugins using public typed APIs. All input routes share native caret insertion and atomic selector/source limits. Native GUI callback tests must disclose synthetic input and verify both client/server inventories plus real save acknowledgements.
- Factory scheduling must respect the existing native world's tick eligibility without loading chunks, renewing tickets, or keeping removed hosts alive. A FULL chunk is not sufficient proof that a factory may execute.
- Recipe-bearing factory item previews must delegate to the embedded native encoded pattern, independently of factory code validity or binding. Let AE2 own Shift and resource rendering; prevent nested factory-pattern delegation and stale outputs after recipe removal.
- Unquantified MUST obligations are channel-local. Migrating an old inflated pending remainder must reduce only uncommitted work and must never restart a transfer that already committed.
- On factory removal, cancel execution and preserve only actual owned resources in the original machine item. Keep resource segments separate when their aggregate exceeds `long`, preserve unresolved native records, subtract only accepted ME insertions, and never materialize expected recipe debt or copy cargo through a memory card.
- Do not place arbitrary queued programs into one dropped item's network payload. Minecraft's native component/NBT quota remains a real boundary; compression alone does not remove it.
- Native acceptance requires exact loaded class/resource identity, all planned scenes exactly once, independent conservation evidence and normal process exit. A failed fixture remains failed evidence even if other scenes passed. Distinguish physical inventories, native CPU orders, standalone production jobs, codec round trips, separate-JVM persistence and synthetic input state.
- PowerShell parameter and report names must remain distinct under case-insensitive lookup. Keep launch and postcondition validation separable: revalidate immutable native evidence through the same complete checks, preserve an original launcher failure, and require an explicit verified checkpoint before resuming remaining gates.
- Large native fixtures must establish connected, active storage and a measured finite initial power budget. Do not silently refill test power or treat inaccessible entity sections as proof that resources disappeared.
- Actual chunk unloading requires native lifecycle callbacks and destroyed old nodes, beyond loss of FULL-chunk accessibility. Separate fixture endpoints beyond the pinned ticket dependency radius and keep complete tests beyond every earlier fixture's remaining ticket influence.
- Shutdown queue fairness must preserve every native task, completion condition and final save. Bound only the demonstrated shutdown call site, and explicitly advance native pending tasks when the outer shutdown clock can otherwise prevent progress; never substitute a forced exit or a pre-save for normal shutdown acceptance.

- Resolve pack recipes from the active server recipe manager and refresh on recipe/tag reload. Never use a namespace whitelist or advertised result alone as proof of a craftable recipe.
- Preserve complete AE item keys, nested custom data and numeric tag types. Compare actual selected inputs and assembled output through native recipe rules; classify random tool effects before evaluating remainders.
- Keep native world-output identity credits private to one CPU job and match them only to exact declared inputs. Explicitly persist network-only map markers without changing global item equality.

- A Crafting Ripper accepts an entire job: validate the whole chain before extracting initial stock, then execute all selected recipe layers synchronously and charge 50 AE once per job. One pattern per tick does not satisfy this contract.
- Order compressed batches by dependencies among the selected recipe SCCs. Downstream consumers must not steal the seed before an upstream growth cycle runs; replay regression schedules against actual credited stock, including cycles feeding acyclic outputs.
- Assign the ring terminal and supercomputing interface ownership from recipes actually selected for the order. Unused reversible recipes in the automatic catalog must not make an otherwise acyclic plan require the ring terminal.
- Treat reversible compression/decompression as conversion of existing material, not a source of net growth. Recognize conservation from exact recipe ratios without item-ID exceptions, and preserve mixed plans that consume available compressed stock before crafting the remaining demand.
- Keep gameplay acceptance helpers outside production source sets and JARs. Launch new isolated PCL worlds, verify exact inputs/outputs and real native CPU calls, capture the framebuffer, and preserve existing saves. Cached network power estimates are not an exact per-call energy meter.

- Prefer small, explicit version adapters over conditional branches scattered through feature code.
- Keep registry names stable, lowercase, and namespaced under the final mod ID.
- Treat server state as authoritative; client code renders and requests actions.
- Use data-driven recipes, tags, loot, and world generation where supported.
- Avoid reflection across Minecraft versions when a narrow adapter is possible.
- Add regression tests alongside behavior with meaningful compatibility risk.
- Keep comments focused on version-specific reasons and non-obvious invariants.
- Optimize measured AE2 hot paths only; preserve network semantics and security checks.

- Bound graph algorithms by both depth and explored states, and never report budget exhaustion as proof that no solution exists.
- Keep material quantities and compressed plan counts in `long`; state-count limits remain `int` because they bound allocated search memory.

- Keep responsibilities strict and independently useful: the recipe-ring terminal alone owns cyclic SCC plans and material reserve policy; the supercomputing interface alone owns ordinary acyclic acceleration. ## Cross-generation native factory transport

- Synchronize factory semantics across both generations, but implement native capabilities against each generation's API. Legacy handlers use simulation, bounded extraction and recoverable remainder handling; modern handlers share one transaction and abort on changed acceptance. Never copy an old dependency JAR into the modern runtime.
- Treat FE identity as both AE key family and exact key id (`appflux:flux` / `appflux:fe`); GTEU is not FE. Reuse PortableEnergyMath instead of classifying the whole Flux family. Native resource identity remains `neoforge::fe`.
- Every nonblocking order owns its VM and MUST remainder. Audit per-order admission minus completion equals activity on every tick, including returned-output code tails; a shared concurrency cap is not a per-pattern cap. Ordinary zero acceptance skips, while inherited GET MUST obligations still wait.
- Describe real external-mod tests separately from registered capability fixtures. A passing interface fixture does not establish compatibility with every uninstalled mod. Keep immutable failed attempts and artifact manifests; acceptance requires the actual final build.


- Factory transport performance: resolve fallback capability faces lazily within one operation, snapshot origins before mutation and never snapshot destinations unnecessarily. Keep no cross-tick inventory/handler/membership cache without explicit invalidation. Batch membership uses one live grid traversal per tag; preserve deterministic packed-position order and same-endpoint/overlapping-label semantics.
- Performance assertions must separate deterministic work reduction from noisy elapsed timing. Compare old/new membership in the same world with alternating sample order and verify equal results around removal/replacement. Full stress timing includes compiler/codec overhead and is diagnostic, not a universal TPS estimate. Do not improve measured throughput by reducing MUST requirements, wait/redstone semantics, job independence or concurrency correctness.

- Validate the complete logistics destination token sequence; an explicit `on` must have a valid face. Recipe unconditional-loop checks use constant expression evaluation without querying the world, preserving dynamic conditions and recipe-free yielding loops.

### Terminal execution refresh contract (2026-09-13)

- Terminal redstone inputs restart on a rising edge, never on each powered tick. Installed-program changes cancel old runs immediately and defer one fresh start until an eligible owner tick. Compare program/binding content so same-code saves and unsaved drafts preserve progress.
- Before cancelling any run, transfer only physically owned input/output and native recovery records to durable recovery. Never turn source quotas or expected debts into cargo, merge long-sized recovery segments, undo already delivered transfers, or leave old pulse/call/wait/MUST state running.
- Persist pending restarts. Suppress edit callbacks during NBT pattern loading and reconstruct the installed-program comparison baseline; ordinary chunk loading is not a code edit. Keep provider order lifecycle separate.
- Diagnose routing against actual saved code and label membership. Channel isolation scopes declarations and quotas; physical tags may overlap, and shared machine inventories are not partitioned by channel. Keep the original player world read-only during reconstruction.
- Report native fixture boundaries explicitly: synchronous server-thread lifecycle calls, binary NBT and seeded cargo do not prove physical mouse input or a new unload/full-stress campaign.
